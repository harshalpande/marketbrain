2026-10-21. This is the ordered acceptance plan, not permission to submit real orders. Combine related positive/negative tests in each evidence bundle, keep timing and safety counters, and retain one shareable report. Do not require live trading before returning to paper development.

Exact provider endpoints, limits and error contracts must be checked against official documentation when implementing stages3/4/8; no sandbox availability, all-channel order coverage or price guarantee is assumed. An HTTP200 callback is not proof of successful token exchange; a valid token is not proof of quote entitlement; review acceptance is not an execution authorization.

Parallel work can prepare offline paper-account/risk/ledger tests while networking is verified. Actual real-quote Telegram tests depend on stages2-4. Live-order tests do not block paper development and remain disconnected. Each package gets its own completion denominator; this plan does not inflate whole-project percentages.
